**Hearth React** is pre-`v1`, and breaking changes land as they're needed on
the way to a stable `v1` API. Each breaking change ships with a codemod in
[`@utilitywarehouse/hearth-codemod`](https://github.com/utilitywarehouse/hearth/tree/main/packages/codemod),
so you can apply it deterministically instead of updating usages by hand.

## Using the codemod CLI

Run codemods with `npx`, no install required:

```sh
npx @utilitywarehouse/hearth-codemod <codemod> <path...>
```

- `<codemod>` — the name of the codemod, e.g. `react/v1/remove-modal-loading-text`.
- `<path...>` — one or more files or directories to transform.

Flags:

| Flag      | Description                                                     |
| --------- | --------------------------------------------------------------- |
| `--dry`   | Dry run — prints what would change without writing any files    |
| `--print` | Print transformed output to stdout (useful during development)  |
| `--force` | Bypass the git-clean check and run against a dirty working tree |

The CLI refuses to run against a dirty git working tree (unless `--dry` or
`--force` is passed), so you can always review the diff and revert if needed.

## Individual codemods

Run these as each breaking change lands, rather than waiting for a full `v1`
release.

### `react/v1/migrate-accordion`

`Accordion` has migrated from Radix UI to Base UI. The codemod applies the
mechanical changes:

```diff
- <Accordion type="single" collapsible defaultValue="item-1">
-   <AccordionContent forceMount>...</AccordionContent>
+ <Accordion defaultValue={['item-1']}>
+   <AccordionContent keepMounted>...</AccordionContent>
```

- `type="single"` and `collapsible` are removed
- `type="multiple"` becomes `multiple`
- a string literal `value` / `defaultValue` is wrapped in an array (`""` becomes `[]`)
- `AccordionContent`'s `forceMount` is renamed to `keepMounted`

```sh
npx @utilitywarehouse/hearth-codemod react/v1/migrate-accordion src
```

Anything it can't safely rewrite is left unchanged and reported as a warning
with the file and line, for manual review:

- `<Accordion>` with no `type` or `multiple` attribute (including via a prop
  spread). It used to default to multi-select, so add `multiple` if that is
  still intended
- a non-literal `type`, `value` or `defaultValue`
- every `onValueChange`, which now receives a `string[]` as its first argument

### `react/v1/migrate-card-accordion`

`CardAccordion` has migrated from Radix UI to Base UI. Its `value` is now a
`string[]` and `onValueChange` receives a `string[]`. The codemod wraps a string
literal `value` in an array (`""` becomes `[]`):

```diff
- <CardAccordion value="step-1">
+ <CardAccordion value={['step-1']}>
```

```sh
npx @utilitywarehouse/hearth-codemod react/v1/migrate-card-accordion src
```

Anything it can't safely rewrite is left unchanged and reported as a warning
with the file and line, for manual review:

- a non-literal `value`
- every `onValueChange`, which now receives a `string[]` as its first argument
- a prop spread, which may carry `value` or `onValueChange` (a literal `value` on the same
  element is still migrated)

This is a breaking change, so it is only included in `react/v1/migration`, not
`react/pre-v1/migration`.

### `react/v1/migrate-card-banner-image`

`CardBannerImage` is deprecated in favour of `BannerImage`, which has the same props. It will
be removed in `v1`.

```diff
- import { CardBannerImage } from '@utilitywarehouse/hearth-react';
+ import { BannerImage } from '@utilitywarehouse/hearth-react';

- <CardBannerImage width="160px" height="174px">
+ <BannerImage width="160px" height="174px">
    <img src={banner} alt="" />
- </CardBannerImage>
+ </BannerImage>
```

```sh
npx @utilitywarehouse/hearth-codemod react/v1/migrate-card-banner-image src
```

The codemod renames the import, including aliased (`CardBannerImage as Banner`) and namespace
(`<H.CardBannerImage>`) imports, and every usage. If `BannerImage` is already imported, the
duplicate import is dropped. Where renaming could collide with another `BannerImage` binding, the
import becomes `BannerImage as CardBannerImage` instead.

This is a non-breaking codemod, so it is included in `react/pre-v1/migration` (and therefore in
`react/v1/migration`).

### `react/v1/migrate-menu`

`MenuItem`'s deprecated `onSelect` and `textValue` props are replaced by
`onClick` and `label`, and `MenuContent`'s deprecated `forceMount` by
`keepMounted`. They will be removed in `v1`.

```diff
- <MenuContent forceMount>
-   <MenuItem onSelect={handleEdit} textValue="Edit">Edit</MenuItem>
+ <MenuContent keepMounted>
+   <MenuItem onClick={handleEdit} label="Edit">Edit</MenuItem>
```

```sh
npx @utilitywarehouse/hearth-codemod react/v1/migrate-menu src
```

Where the replacement prop is already set to a literal (`label="..."`,
`keepMounted={false}`), the deprecated prop was unused and is removed.

Anything it can't safely rewrite is left unchanged and reported as a warning
with the file and line, for manual review:

- a `MenuItem` with both `onSelect` and `onClick`, since both handlers run today
- `textValue` alongside a non-literal `label`, or `forceMount` alongside a
  non-literal `keepMounted`
- a prop spread (e.g. `<MenuItem {...props} />`) that may carry a deprecated prop

### `react/v1/remove-accordion-content-force-mount`

`AccordionContent`'s deprecated `forceMount` prop is replaced by `keepMounted`.
It will be removed in `v1`.

```diff
- <AccordionContent forceMount>
+ <AccordionContent keepMounted>
```

```sh
npx @utilitywarehouse/hearth-codemod react/v1/remove-accordion-content-force-mount src
```

Where `keepMounted` is already set to a literal (`keepMounted={false}`),
`forceMount` was unused and is removed.

Anything it can't safely rewrite is left unchanged and reported as a warning
with the file and line, for manual review:

- `forceMount` alongside a non-literal `keepMounted`, or a non-literal `forceMount`
- a prop spread (e.g. `<AccordionContent {...props} />`) that may carry either prop

### `react/v1/remove-modal-fullscreen`

`Modal`'s `fullScreen` prop has been removed. It had no effect, so deleting it
never changes behaviour.

```diff
- <Modal fullScreen>
+ <Modal>
```

```sh
npx @utilitywarehouse/hearth-codemod react/v1/remove-modal-fullscreen src
```

If `fullScreen` reaches `Modal` through a prop spread (e.g. `<Modal {...props} />`),
the codemod leaves the element unchanged and prints a warning with the file and
line so you can remove it manually.

### `react/v1/remove-modal-loading-text`

`Modal`'s deprecated `loadingText` prop has been removed in favour of
`loadingHeading`.

```diff
- <Modal loadingText="Loading...">
+ <Modal loadingHeading="Loading...">
```

```sh
npx @utilitywarehouse/hearth-codemod react/v1/remove-modal-loading-text src
```

### `react/v1/remove-text-wrap-prop`

`BodyText`, `Heading`, `Strong`, `Em` and `DetailText`'s deprecated `wrap`
prop has been removed in favour of `textWrap`.

```diff
- <BodyText wrap="balance">
+ <BodyText textWrap="balance">
```

```sh
npx @utilitywarehouse/hearth-codemod react/v1/remove-text-wrap-prop src
```

If an element has both `wrap` and `textWrap`, or `wrap` reaches it through a
prop spread (e.g. `<BodyText {...props} />`), the codemod leaves it unchanged
and prints a warning with the file and line so you can merge or review it
manually.

## Running the pre-v1 migration

`react/pre-v1/migration` runs only the non-breaking codemods listed above, so
it is safe to run on the current release, before upgrading to `v1`:

```sh
npx @utilitywarehouse/hearth-codemod react/pre-v1/migration src
```

## Running the complete v1 migration

Once you're ready to migrate everything at once, `react/v1/migration` runs
the pre-v1 migration plus any breaking-change codemods in a single pass:

```sh
npx @utilitywarehouse/hearth-codemod react/v1/migration src
```

We recommend running with `--dry` first to review the changes before applying
them for real.
