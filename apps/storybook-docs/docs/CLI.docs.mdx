# Hearth CLI

The Hearth CLI (`@utilitywarehouse/hearth-cli`, command `hearth`) looks up design
tokens, icons, SVG assets and JSON assets from the Hearth packages installed in
your project. Use it to check that a token, icon or asset exists, and to get its
CSS variable, component name or import, instead of guessing a name.

## Try it

```console
npx @utilitywarehouse/hearth-cli tokens search brand
npx @utilitywarehouse/hearth-cli tokens get semantic.background.brand
npx @utilitywarehouse/hearth-cli icons search bill
npx @utilitywarehouse/hearth-cli assets svg list --category logo
```

Add `--json` to any lookup for machine-readable output, which is what scripts
and AI agents should use.

## What it covers

| Command              | Looks up                                                            | Reads from                                                       |
| -------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `hearth tokens`      | Design tokens, with their CSS variable, browser and JS paths         | `@utilitywarehouse/hearth-tokens`                                |
| `hearth icons`       | Icons, with their component and an import line for the package you have | `hearth-react-icons`, `hearth-react-native-icons` or `hearth-svg-icons` |
| `hearth assets svg`  | SVG illustrations and logos, and the SVG file itself with `--print`  | `@utilitywarehouse/hearth-svg-assets`                            |
| `hearth assets json` | Animated JSON assets                                                | `@utilitywarehouse/hearth-json-assets`                           |

Every command has `search`, `list` and `get`.

## Answers match your installed versions

The CLI holds no data of its own. Each of those packages ships a
`hearth-manifest.json`, and the CLI reads it from your `node_modules`. So the
answer is always about the version you have installed, the first line of the
output names that version, and upgrading a Hearth package changes the answers
without a new CLI release.

If a package is not installed, is too old to ship a manifest, or ships one from
a newer schema than your CLI supports, the CLI exits with code `3` and says what
to install or update. The one exception is a package whose `exports` hides its
manifest, which no Hearth release does; the [README](https://github.com/utilitywarehouse/hearth/blob/main/packages/cli/README.md#how-the-data-stays-current)
has the detail.

## How it complements the Storybook MCP servers

Hearth has two Storybook MCP servers, `hearth-react` and `hearth-react-native`.
They cover **components**: props, usage docs and stories, through `docs-list`,
`docs-show` and `docs-show-story`. See [AI Toolkit](?path=/docs/ai-toolkit--docs) for
setting them up.

The CLI covers everything else a component library is built from:

| You want to know                                                | Use                                    |
| --------------------------------------------------------------- | -------------------------------------- |
| Which props a component takes, how to use it, example stories   | The `hearth-react` or `hearth-react-native` MCP server |
| Whether a token exists, its CSS variable, its dark value        | `hearth tokens`                        |
| Which icon to use, and the import for the package you installed | `hearth icons`                         |
| Which illustration or logo exists, and where its file is        | `hearth assets svg` or `hearth assets json` |

The two work together: an agent can ask the MCP server how a component is used,
then ask the CLI which semantic token to use for its colours.

A few things differ in practice:

- **Version.** The MCP servers are hosted, so they describe the version that is
  deployed, which may not be the one in your project. The CLI describes the
  version in your project.
- **Setup.** The CLI needs no server and no configuration: it is a command that
  reads files, so any tool that can run a shell command can use it.
- **Context cost.** There are no tool definitions to load into an agent's
  context. It runs the command it needs and reads the output.
